# MaxSecure 2.0

Локальное PWA-приложение для хранения заметок в виде шифр-кодов с проверкой Google Authenticator.

## Что изменено в 2.0

- Основной режим теперь — «Заметки».
- Навигация/переключатель режимов перенесён в нижнюю часть экрана.
- Добавлено локальное хранилище заметок на IndexedDB.
- При создании заметки можно указать:
  - заголовок;
  - текст;
  - актуальный 6-значный код Google Authenticator.
- После сохранения текст проходит через **ту же криптографическую функцию `VaultCrypto.encryptText()`**, которая была в исходной версии.
- В IndexedDB заметки хранятся как:
  - заголовок;
  - шифр-код;
  - даты создания/изменения.
- Обычный текст заметки в хранилище приложения не сохраняется.
- Для открытия заметки сначала требуется актуальный TOTP-код, после чего сохранённый шифр-код расшифровывается локально.
- После открытия заметку можно изменить:
  - текст;
  - заголовок.
- При сохранении изменений снова требуется актуальный TOTP-код.
- Старый шифр-код заменяется новым шифр-кодом, созданным заново через исходную криптографическую схему.
- Автосохранения черновика нет. Если закрыть приложение до нажатия «Сохранить изменения», исходная сохранённая заметка остаётся без изменений.
- Удаление требует:
  1. актуальный TOTP-код;
  2. подтверждение удаления;
  3. ожидание 10 секунд.
- Кнопка окончательного удаления заблокирована первые 10 секунд.
- После удаления заметка удаляется из локального IndexedDB-хранилища.
- Старый ручной режим «Шифрование» / «Расшифровка» сохранён.

## Криптография

`js/crypto.js` в версии 2.0 **идентичен исходному файлу**.

Используется исходная схема:

- AES-256-GCM;
- случайная 256-битная соль для каждого сообщения;
- случайный 96-битный nonce;
- HKDF-SHA-256;
- постоянный TOTP-секрет как корневой секрет;
- TOTP используется как проверка доступа;
- шифр-код имеет формат `VT2.<header-base64>.<ciphertext-base64>`.

Новая функция заметок не реализует собственную криптографию и не меняет алгоритм исходного проекта.

## Хранение

Используются два независимых IndexedDB-хранилища:

- `VaultTextDB` — исходное хранилище неэкспортируемого TOTP CryptoKey;
- `VaultTextNotesDB` — список заметок.

В `VaultTextNotesDB` хранится шифр-код, а не расшифрованный текст.

Заголовок хранится отдельно и виден в списке заметок до авторизации. Это сделано специально, чтобы приложение работало как обычный список заметок.

## Редактирование

При открытии заметки:

1. пользователь нажимает на заголовок;
2. вводит актуальный TOTP;
3. приложение проверяет код;
4. приложение расшифровывает существующий шифр-код;
5. текст помещается только в оперативное состояние редактора.

При сохранении:

1. пользователь вносит изменения;
2. вводит новый актуальный TOTP;
3. исходная функция `encryptText()` создаёт новый шифр-код;
4. новый объект заметки записывается в IndexedDB поверх старого;
5. сохранённый текст в открытом виде в IndexedDB не появляется.

Если приложение закрыть до сохранения, новый текст не записывается в IndexedDB.

## Удаление

Удаление защищено двумя этапами:

1. проверка актуального TOTP;
2. отдельное окно:
   «ВЫ ТОЧНО ЖЕЛАЕТЕ БЕЗВОЗВРАТНО УДАЛИТЬ ЗАМЕТКУ?!»
3. 10-секундный обратный отсчёт;
4. только после этого кнопка становится доступной.

Важно: браузерная IndexedDB не предоставляет гарантии физического затирания старых блоков данных на уровне накопителя. Поэтому «безвозвратно» здесь означает удаление записи из доступного приложению хранилища, а не гарантированное криптографическое уничтожение всех физических копий на SSD/файловой системе.

## Запуск

Проект рассчитан на HTTPS или `localhost`, потому что Web Crypto/PWA/Service Worker требуют безопасного контекста.

Для локального запуска можно использовать любой статический HTTP-сервер.

Например:

```text
python -m http.server 8000
```

После запуска открыть:

```text
http://localhost:8000/
```

## Важное ограничение

Приложение не является сертифицированным криптографическим продуктом. Web Crypto не гарантирует универсальную аппаратную привязку IndexedDB к Secure Enclave/TPM на всех браузерах.

Для особо критичных данных необходим независимый криптографический аудит и отдельный аппаратный фактор.
